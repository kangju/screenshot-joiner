# Product Requirements

## 1. Product summary

業務上のスクリーンショットを複数読み込み、順番と見た目を調整して1枚へ結合し、クリップボードへコピーまたは端末へ保存するWebツールを作る。

最大の価値は「スクリーンショットを保存・変換する手間なく、貼り付けて並べてすぐ業務ツールへ転記できること」。

## 2. Target users and use cases

- 開発者・QA担当者が複数の画面をJira、Backlog、GitHub、Slack、Teamsへ貼り付ける。
- システムエンジニアが手順書、設計書、試験エビデンス用の画像をまとめる。
- ZIPで渡された大量のスクリーンショットから画像だけを取り込む。
- PCだけでなくスマートフォン上でも写真やスクリーンショットをまとめる。

## 3. Functional requirements

### FR-01 Image input

- PNG、JPEG、WebPを複数選択できる。
- ファイルとZIPをドラッグ＆ドロップできる。
- ページ上で`Ctrl+V`または`Cmd+V`を押すと、クリップボード内の画像を末尾へ追加する。
- スマートフォンでは画像選択とZIP選択を明示的なボタンから実行できる。
- 読み込み中と失敗したファイルをユーザーへ表示する。

### FR-02 ZIP input

- 非暗号化ZIPをブラウザ内のWeb Workerで展開する。
- PNG、JPEG、WebPだけを抽出する。
- フォルダ、`__MACOSX`、隠しメタデータ、画像以外のファイルを無視する。
- 拡張子とマジックナンバーの両方で画像を検証する。
- ZIP内画像をファイル名の自然順で追加する。例：`1, 2, 10`。
- 多重ZIPとパスワード付きZIPは展開せず、理由を表示する。
- 展開処理をキャンセルできる。

### FR-03 Reordering

- 画像一覧の専用ハンドルをドラッグ＆ドロップして順番を変更できる。
- PCではマウスまたはポインター移動約6pxでドラッグを開始する。
- スマートフォンではハンドルを約180ms長押ししてドラッグを開始する。
- ハンドル以外の縦スクロールを妨げない。
- 長い一覧ではドラッグ中に画面端で自動スクロールする。
- キーボードでも画像順を変更できる。
- 移動後は結合プレビューへ即時反映する。

### FR-04 Crop

- 各画像を個別にトリミングできる。
- 自由比率で範囲を選べる。
- 決定、キャンセル、リセットを提供する。
- 元画像を変更せず、切り抜き範囲をメタデータとして保持する。
- スマートフォンではピンチとドラッグがスクロール操作と衝突しない。

### FR-05 Rotation

- 各画像を右へ90度回転できる。
- 連続操作で0、90、180、270度を循環する。
- 必要なら元の向きへリセットできる。
- 読み込み時はEXIF方向を考慮する。

### FR-06 Resize

- 原寸、幅揃え、高さ揃え、指定サイズを選べる。
- 縦結合の初期値は幅揃え、横結合の初期値は高さ揃えとする。
- 縦横比は維持し、画像を歪ませない。
- 出力予定の幅、高さ、総画素数を表示する。

### FR-07 Join settings

- 縦結合と横結合を選べる。
- 画像間隔を0px以上で指定できる。初期値は0px。
- 背景色を指定できる。初期値は白。
- 設定と画像順の変更をプレビューへ反映する。
- グリッドと自由配置は初期リリース対象外とする。

### FR-08 Export

- 結合結果をPNGとしてクリップボードへコピーできる。
- PNGまたはJPEGとしてダウンロードできる。
- JPEG品質を指定できる。
- Clipboard API非対応または拒否時は、PNG保存を代替手段として提示する。
- コピーと保存は明示的なユーザー操作から開始する。

### FR-09 Item controls

- 各画像に並べ替え、回転、トリミング、削除操作を提供する。
- 判別しやすい操作はLucideアイコンだけで表示する。
- アイコン単独ボタンには`aria-label`とツールチップを設定する。
- 画像／ZIP追加、保存、コピーなど主要操作はアイコンと短い文字を併用する。

### FR-10 Clear and cleanup

- 画像を個別削除できる。
- 全画像を一括削除できる。
- 削除時にObject URLをrevokeし、ImageBitmapをcloseする。
- ページ離脱時に全メモリ資源、Worker、イベントリスナーを解放する。

## 4. Non-functional requirements

### Privacy

- ユーザー画像、ZIP、ファイル名、結合画像をネットワーク送信しない。
- 画像を永続化しない。
- 初期リリースではアクセス解析、広告、外部フォント、外部画像を使用しない。
- UI上に「画像は端末内だけで処理されます」と明示する。

### Performance

- ZIP展開を専用Web Workerで処理し、メインスレッドを長時間ブロックしない。
- プレビューは表示用に縮小し、出力時だけ必要解像度でCanvasを生成する。
- 画像変更時に不要な全画像デコードを繰り返さない。

### Accessibility

- すべての操作をキーボードで到達・実行できる。
- フォーカス表示を消さない。
- 状態通知には`aria-live="polite"`、処理不能エラーには`role="alert"`を使う。
- 色だけで選択・エラー状態を表現しない。

### Responsive UI

- 320px以上で横スクロールや操作要素の重なりを発生させない。
- スマートフォンの操作対象は44×44 CSS px以上とする。
- PCでは一覧の各行に編集アイコンを表示する。
- スマートフォンでは各行のメニューから回転・トリミング・削除を行う。
- スマートフォンの主要な保存・コピー操作は押しやすい位置へ置く。

## 5. Initial safety limits

| Limit | Initial value |
| --- | ---: |
| ZIP compressed size | 200 MB |
| Extracted image count | 200 |
| One extracted image | 30 MB |
| Total extracted bytes | 300 MB |
| Output pixel warning | 100 MP |

制限値は設定定数として一元管理し、テストで境界値を固定する。

## 6. Out of scope

- アカウント、ログイン、クラウド同期、共有URL
- API、サーバー画像処理、DB、外部ストレージ
- 文字、矢印、図形、ぼかし、透かし、AI編集
- グリッド、自由配置、テンプレート
- GIFアニメーション保持、BMP、AVIF
- PDF出力
