### 2026-09-09 — カスタムサイズ1px未満で出力0px・保存無言失敗(Codex CLI批判的レビューで発見)

- Wrong assumption: `handleCustomSizeChange`(`src/app/page.tsx`)の`size > 0`という検証は、UIの`<input min={1}>`と実質同じ下限だと仮定していた。実際には`type="number"`の`min`属性はキーボード入力そのものをブロックせず、`0.1`のような値がそのままステートに反映され、`render.ts`のMath.round丸めで出力が0pxになっても`canvas.toBlob`のコールバックが`blob`のfalsyを無視していたため、保存操作全体が無言で失敗していた。
- Minimal repro: 120×80画像を1枚追加し、「サイズを指定」で`0.1`を入力してPNG保存をクリックすると、出力が0×0に丸まり、ダウンロードもエラー表示も発生しない。1×10000程度の極端なアスペクト比の画像では、customSize自体が1px以上の有効な値(例: `1`)でも、全体レイアウトの丸め後の高さが0pxになる同種の失敗が起きる。
- Root cause: (1) `handleCustomSizeChange`の下限検証がUIの`min`属性と不一致、(2) レイアウト計算後・canvas確保前に丸め後の寸法(全体・個別画像のplacement双方)を検証する仕組みが存在しなかった、(3) `toBlob`失敗時に何も通知しない、の3点が重なった複合要因。
- Permanent fix: `handleCustomSizeChange`の下限を`size >= 1`に統一。`hasInvalidOutputDimensions`(`src/lib/output-guard.ts`、新設)が丸め後の全体寸法・各placementの寸法をNumber.isFinite && >= 1で検証し、100MP警告より前に不正な場合を検出して保存を拒否・`role="alert"`で通知する。`toBlob`が`null`を返す経路(PNG/JPEG保存・コピーの3箇所)にも同様の通知を追加。エラー状態はreducerではなく`page.tsx`内のローカル`useState`(`outputError`)に置き、Issue #64(初期サイズモード)のレーンとファイルが衝突しないようにした。
- Regression test: `tests/unit/output-guard.test.ts`の`hasInvalidOutputDimensions`(全体無効・NaN・個別placement無効の各ケース)、`tests/unit/page.test.tsx`の新規6ケース(下限未満入力の拒否、極端なアスペクト比での全体無効化、個別placement無効化、是正後の保存成功、`toBlob(null)`のPNG/JPEG/コピー3経路、全削除時のエラー解除)。Codexの計画レビュー(2026-09-09、`~/.claude/skills/codex-review`)で個別placementの丸めチェック漏れとreducer衝突リスクを指摘され、実装前に計画へ反映済み。実機確認は`browser-check`(Playwright MCP)で、実際にPNGをダウンロードしてPillowで寸法・画素値を照合(2000×1、色値一致)、320px幅でのalert表示・横スクロールなし・フォーカス表示を確認。`full-check`(test 244件/typecheck/lint/build)全てgreen。
